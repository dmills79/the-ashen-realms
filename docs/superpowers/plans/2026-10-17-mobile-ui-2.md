# Mobile UI 2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the mobile D-pad and dense exploration HUD with a responsive analog joystick and compact, collapsible fantasy controls while preserving the existing game engine and desktop experience.

**Architecture:** A pointer-driven joystick records normalized intent and the existing animation-frame input loop translates that intent into cardinal `moveCommand()` calls, so `tryMove()`, `walkable()`, encounters, animation, and saves remain authoritative. A small presentation-only HUD controller coordinates quest, minimap, BAG, and settings surfaces; CSS isolates the new layout to exploration viewports below 900 pixels.

**Tech Stack:** Dependency-free HTML/CSS/JavaScript, Canvas rendering, Pointer Events, Node.js tests, Playwright Chromium.

**Spec:** `docs/superpowers/specs/2026-10-17-mobile-ui-2-design.md`

## Global Constraints

- Work only on `feature/mobile-polish`; preserve Lantern Road and all existing content.
- Keep `moveCommand(dx, dy)`, `tryMove(dx, dy)`, and `walkable(loc, x, y)` as the only movement/collision path.
- Preserve keyboard and mouse behavior, save key `ashen-realms-v1.2-save`, save versions 2–5, and desktop HUD presentation.
- Add no runtime dependency, framework, icon library, or build step.
- Keep ACT independently usable while a separate joystick pointer remains active.
- Use the existing safe-area variables and validate 844×390, 852×393, 932×430, 740×360, 390×844, and 1440×900.
- Do not merge to `main`, deploy, or modify production infrastructure.

## Review Focus

- A second pointer beginning on the joystick cannot steal or cancel the active movement pointer; Task 1 adds an ownership test.
- A vector inside the dead zone never moves the character; Task 1 adds a dead-zone test.
- Browser blur, visibility loss, modal opening, combat entry, and pointer-capture loss cannot leave movement stuck; Task 1 adds lifecycle-reset coverage.
- Resizing or rotating with a tray open keeps every interactive surface inside the viewport and preserves access to ACT; Task 3 adds resize coverage.
- Opening a modal from an expanded quest, map, BAG, or settings surface closes presentation-only state without affecting gameplay; Task 2 adds modal coordination coverage.
